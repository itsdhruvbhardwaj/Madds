# Style groups

Studio: Styles > Groups > New group, or select 2–8 existing styles and choose Group selected. Give the family a name, choose the cover, order its members, optionally add short variant labels, then save a draft or publish. The original styles remain editable in Styles; their editor identifies their group. A style can belong to only one active group, including drafts. Ungroup archives only the group metadata, keeping all styles and media.

Publishing requires two verified members and a verified cover. Public projection uses the current verified catalogue, preference and collection filters before grouping. If fewer than two eligible members remain, they appear as individual styles. Unverified, deleted and filtered-out members never appear in the selector. A missing/ineligible cover falls back to the first eligible member. Groups are team-managed; no automatic production grouping is performed.

Backend stores references in the StyleGroup collection. A unique partial multikey index protects active membership even across simultaneous writes. Creation, edits and archival use transactions and audit logs; edits/archival require the expected updatedAt timestamp. This needs the same transaction-capable MongoDB deployment already used by bulk tag writes. Group writes require an approved, email-verified Studio administrator.

Updated Android and web clients request grouped=true on discovery, collections and detail APIs. Older clients keep flat cards and existing style IDs, including generation requests. Deploy backend first, then Studio and updated clients. No existing style migrations or Android version changes are included. Search uses group names, variant labels and the existing tag aliases; the best matching member is selected. Pagination counts cards after grouping. Seeded shuffle uses the stable group ID and keeps Trending groups first when requested.

Preview uses a horizontally scrollable thumbnail strip and explicit previous/next buttons. This avoids conflicting with dragging the before/after comparison. Selection changes the real style ID, reference-photo count, price, description and heart. Generation still starts only through the existing Generate/upload flow. Favorites remain per individual style. Android caches every variant under its real ID, and public disk snapshots strip nested prompts and account favorite state. Existing stable media URLs and image-cache policy are unchanged.

Local validation covers grouping projection, search, filtered members, stable shuffle, validation, guarded transactional writes, stale edits, membership conflicts, ungroup preservation, old API compatibility, variant selection while favorite writes are pending, and cache sanitation. Studio has a disposable local fixture (WORKSPACE_PREVIEW_PORT controls its port). No real groups or external notifications are created by fixture tests.
